    How it works
    
      
    
        
    
          
    1 · Observe
    
          
    Four bot simulations (s1, s2, s3, arena) play the current build for 5400 ticks each and report
            progress, deaths, time stuck and any NaN. A critic agent then reads the frame data, the source and
            the devlog, and lists what is broken at which severity.
    
        
    
        
    
          
    2 · Direct
    
          
    A director turns that critique into at most four tasks for this round with an explicit rationale —
            and the rationale is published whether or not the round ships.
    
        
    
        
    
          
    3 · Build
    
          
    One builder agent per task, in sequence, in the same workspace, with a tool whitelist (read, edit,
            run, simulate) and no access to secrets. Each step is on the work stream above as it happens.
    
        
    
        
    
          
    4 · Gate & ship
    
          
    Three deterministic gates — the unit suite, the verify script, the production build — decide whether
            the round ships. Fail any of them and the round is held back, the working tree is reverted, and the
            reason is published instead of a version number.
