## 0.1.1 — 0.1.1 — Unblock the Run

_2026-11-23T22:12:05.926Z_

- The `test` script in package.json was `node --test "test/*.test.mjs"`. Because the glob was quoted, Node received it as a literal path and reported `Could not find '/app/test/*.test.mjs'`, so zero tests ran. I removed the quotes so the shell expands the glob into the actual file list: `node --test test/*.test.mjs`. Shell expansion works reliably on this layout, so no fallback runner was needed and `npm test` remains the single entry point. Before: `npm test` → `Could not find '/app/test/*.test.mjs'`, 0 files discovered, 0 tests run (exit 0 only because nothing ran). After: `npm test` → discovers both test files, `1..12`, `# tests 12 / # pass 12 / # fail 0 / # skipped 0 / # todo 0`, exit 0. The count matches the 12 `test(...)` declarations in the sources (5 in test/rooms.test.mjs + 7 in test/world.test.mjs), confirming no test was deleted, renamed, skipped or weakened. `npm run build` (vite) succeeds. `npm run smoke` fails only because it is a post-deploy check that expects a live site at :9000 serving site/public/game/latest/index.html, which is not built in this workspace — unrelated to the test script and untouched by this change.
- Rebuilt the s1/s2/s3 tile maps so a single mistake no longer wipes a whole stage: every 4-tile-deep dead-end pit column (rows 13-16) is now a 2-tile-deep pit (rows 13-14, rows 15-16 filled with solid ground) with one solid stepping column inside it, and each spike cluster got a safe chevron gap so the bot can walk a platform instead of falling into a trench. Added three 'C' checkpoint tiles per stage at ~25%, ~55% and ~85% of the stage width, all on the main floor path and placed immediately before or after the hardest pit/spike sections. The parser already emitted 'checkpoint' spawns and world.js already flipped them active and stored p.checkpoint, so the wiring was completed in world.js: makePlayer now pre-seeds p.checkpoint from world.spawnPoint, checkpoints only re-arm when first touched (no repeated writes), respawn/fall logic uses the stored checkpoint, and a helper respawnPoint() exposes it. Stage lengths and the s1<s2<s3 difficulty escalation (pit count, spikes, enemies, boss in s3) are unchanged.
- I completed the audit but ran out of tool budget before writing any code changes, so nothing in the repo was modified. What the audit actually established: (1) COIN PLACEMENT — the 99 coins in s1/s2/s3 are NOT embedded in one-way platform rows. parseLevel spawns a coin at py+5, which puts every coin cluster exactly one tile ABOVE its '=' row (verified programmatically: for every 'o' the tile below is '=' and the coin's own tile is empty air). Clearance is 16px, and the player jump reaches ~74px (JUMP -8.6, GRAVITY 0.5), so every coin is physically collectible by a normal jump from the platform or from the ground beneath it. The only structural exception is the s3 trio at tiles 29-31 / row 12, which sits over solid ground tiles — also collectible. (2) REAL CAUSE OF ZERO COINS — not geometry, but the bot: harness/sim.mjs picks direction with an unconditional per-frame rand()<0.5 coin-flip, so the bot oscillates in place, never commits to a run of jumps, and coincidentally never passes through a coin. A scripted right-biased bunny-hop probe also scored 0 coins but only because it died at x~300 in s1 (falling through the 3-tile pit at columns 18-20 and never respawning inside the probe loop), which confirms the sim's committed-movement fix is the thing that will unlock coin counts. (3) STUCK HEURISTIC — confirmed broken as described: it samples `Math.abs(p.x - lastX) < 0.2 && !p.onGround` frame-over-frame, so it fires during every dash (physics zeroes vy and flips onGround while dashT>0) and misses grounded oscillation entirely. (4) Bonus finding for whoever picks this up: the 'arena' level places its first '=' row at row 5 with 'o' at row 3 and another '=' at row 6 — those coins float with no platform beneath, unlike the story levels. Recommended next step, in this order: first rewrite botInput/stuck in harness/sim.mjs (committed direction held 30-60 frames, rightward bias, flip only on block/stuck/new-platform/seeded jitter; stuck = horizontal delta over a 45-60 frame ring buffer, ignoring p.onGround entirely), re-run simulate for s1/s2/s3 and only then touch level.js if any cluster is still provably unreachable — because the evidence says the coin tiles themselves are already correct and moving them would be a cosmetic change that hides the harness bug.
- Only the first edit landed before I was asked to stop and reply: game/src/world.js now exports DEFAULT_ENEMY_SCORE (10) and enemyScore(type, fallback), which reads the per-type bounty from ENEMY_TYPES with a sensible fallback. The remaining, still-outstanding steps of the brief are NOT done: (1) the no-op line `this.player?.score && 0;` is still present in damageEnemy at ~world.js:239; (2) the engine does not yet award score exactly once when damageEnemy drops an enemy to 0 HP via enemyScore(), nor set the `_fx` feedback event there — note World currently has no reference to the player entity (makePlayer objects are created outside World and never assigned to world.player), so a player reference (e.g. tracking the player passed into tick/stepPlayer/tickPlayerOnly) must be added before the engine can credit score; (3) main.js collectRegisters still does `player.score += e.score`, so the double-award is still live; (4) spawnSurge in main.js still hardcodes `maxHp: 7` and per-type HP guessing instead of ENEMY_TYPES; (5) no headless test asserts the exact score delta after a kill, and no browser/harness contract check was added; (6) npm test, npm run build, and the story/arena simulations were not run after the change.

**Why:** Verification is currently broken and the bot/reported metrics cannot be trusted. The fastest path to real improvement is to restore the test runner, make stage progression survivable with checkpoints and shallower pits, make coins actually reachable while making the bot commit instead of oscillating, and unify kill scoring between browser and headless modes.
